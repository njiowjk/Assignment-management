# UniversityTaskManager

Moodle と WebClass に分散する大学課題を、締切順にまとめて確認するための macOS ネイティブアプリです。

現在は **Phase 6（配布・運用安定化）** です。画面はSwiftUI、バックエンドはアプリに同梱したTypeScript/Node.jsです。Node同梱・DMG作成・移動後の自己診断に対応しました。一般配布用のDeveloper ID署名・Apple公証は、証明書の準備後に実施します。取得した課題を次の順で表示します。

1. 期限切れ
2. 今日
3. 明日
4. 今週
5. それ以降

各グループ内は締切の早い順です。通常の一覧は、未完了が確認できた課題だけを表示します。完了済みは自動的に除外し、判定できなかった課題は「確認できなかった課題」に分けて保存します。

### 締切で絞り込む

一覧上部の「期限内／すべて／期限切れ」で切り替えます。初期表示は「期限内」で、期限切れの課題を隠します。「すべて」で再表示でき、非表示件数も案内します。提出状況が不明の課題にも同じ締切条件を適用しますが、未完了の一覧には混ぜません。

選択は再起動後も保持し、メニューバーの一覧・件数にも反映します。締切が現在時刻を過ぎたかで判定し、起動中は毎分の表示更新で見直します。これは表示だけの設定で、課題データの削除・完了扱い・同期や通知の停止は行いません。

## 配布版のインストール

DMG内の `UniversityTaskManager.app` を `Applications` へドラッグし、Applicationsから開きます。完成したアプリの実行に、Node.js・npm・Xcode・ターミナルは不要です。初回のMoodle / WebClassログインと通知の許可は、各Macで行います。

このMacで作る標準のDMGは **local-preview（ローカル検証用）** で、Apple公証済みの一般配布版ではありません。Gatekeeperを無効化したり隔離属性を削除したりする手順は含めません。他の利用者へ一般配布する前に、下記のDeveloper ID署名・公証と実機確認を完了してください。

「Macログイン時に起動」はApplicationsへ移してから設定してください。ビルドフォルダーから登録済みの場合は、旧版側で一度OFFにし、インストール版からONにし直してください。アプリを移動・更新する際は起動中の版を終了し、データの保存先やKeychainは削除しません。

現時点で実機検証している成果物はApple Silicon（arm64）、このMacのmacOS 26環境です。設定上の最低OSはmacOS 13ですが、macOS 13・Intel Macでの動作確認は別途必要です。Universal版ではありません。

## ターミナルから開発版をビルド・起動

ソースからのビルドにはSwift Command Line ToolsとNode.js 22以降（npmを含む）が必要です。これは完成したアプリの実行要件ではありません。このMacではインストール済みです。Xcodeアプリを開かなくても、次のコマンドでビルドして起動できます。

```sh
cd /Users/sakakihondaihase/Desktop/assin
./run.sh
```

初回は依存を `npm ci` で取得し、公式Node.js 22.23.4のアーカイブをダウンロードして、固定SHA-256で照合します。`.build/UniversityTaskManager.app` にバックエンド・Node本体・ライセンスを同梱し、内側のNodeから順にHardened Runtime付きad-hoc署名を付けます。署名用の証明書は不要ですが、一般配布用の署名・公証ではありません。アプリを終了するときは `Command + Q` を押します。ターミナルの `Control + C` は起動待ちの終了用です。

課題ウィンドウを表示し、保存済みの認証情報をバックグラウンドで確認します。起動時は認証画面を出しません。Keychainの許可が必要な場合は、設定の「保存済み連携情報を読み込む」を押してください。この操作ではWebClass、MoodleカレンダーURL、Moodleセッションの最大3項目に許可確認が出る場合があります。ウィンドウが背面や最小化状態になった場合はDockのアプリアイコン、またはアプリの「ファイル」→「課題一覧を開く」（Command + 1）で戻せます。

ビルドだけなら `./run.sh --build-only`、最適化版なら `./run.sh --build-only --release` を実行します。ビルド時のNode.jsがHomebrew版でも、完成したアプリはHomebrewへ依存しない公式Node本体を内部から起動します。取得済みアーカイブは `.build/node-runtime/` にキャッシュし、再利用時もハッシュを照合します。

サンプル画面だけを確認する場合は `./run.sh --demo` を実行します。デモでは実際のDBやKeychainにアクセスしません。

## DMGの作成・検証

```sh
./release.sh
```

最適化ビルド・Node同梱・署名・別フォルダーへ移動した自己診断・DMG作成・DMG整合性確認・読み取り専用マウント内からの自己診断を実行します。起動中のアプリは再起動しません。作成物は毎回新しい `dist/UniversityTaskManager-.../` フォルダーへ出力し、既存成果物を上書きしません。

- `*.dmg`：Applicationsへのドラッグ用リンクと「はじめに」を含むインストールイメージ
- `SHA256SUMS.txt`：最終DMGのSHA-256
- `verification.json`：CPU・Nodeバージョン・署名／移動／DMG内診断の結果と公証状態

全検証が終わるまでイメージ名を `.incomplete.dmg` とし、失敗した成果物を配布完了版として扱いません。ソース、node_modules、大学のURL・Cookie・DB・ユーザー設定は配布物へコピーしません。

アプリ単体を検証する場合：

```sh
node scripts/verify-app.mjs .build/UniversityTaskManager.app
.build/UniversityTaskManager.app/Contents/MacOS/UniversityTaskManager --self-test
```

自己診断は模擬データだけでバックエンドの起動、ICSタイムゾーン、課題更新、同期予定、通知予定を確認し、JSONで結果を返します。画面・DB・Keychain・通知許可・大学への通信には触れません。検証スクリプトは、空白を含む別パスとHomebrew抜きのPATHで実行し、環境変数によるバックエンド差し替えも無視されることを確認します。

## Moodleの接続

1. Moodleの「カレンダー」→「カレンダーをエクスポート」を開きます。
2. 授業の予定と、十分な期間（例：最近と今後60日）を選び、「URLを取得」で生成したHTTPSのURLをコピーします。
3. アプリの「設定」でURL欄を選んで `Command + V`、または欄の横の「貼り付け」を押し、「保存して同期」を押します。
4. 同じ設定画面で「Moodleにログイン」を押し、表示された大学公式ページでログインします。
5. 「連携して同期」を押すと、提出情報を取得して完了済みの課題を一覧から除外します。

URLは認証トークンを含むため、チャットやGitHubには貼り付けず、アプリの設定に入力してください。Keychainだけに保存し、通常の設定・DB・ログには保存しません。

ログイン画面はWKWebView内の大学公式サイトです。アプリ独自のパスワードフォームはなく、パスワードは読み取り・保存しません。連携ボタンを押したときにMoodle向けCookieだけをKeychainに保存します。CIS Moodleは学外からの利用に大学VPNが必要な場合があります。

カレンダーURLだけを登録した状態では提出情報を取得できません。セッションが切れた場合は設定で再ログインしてください。認証エラーで課題を削除したり、完了扱いにしたりすることはありません。

## 自動完了判定

- 課題提出：Moodleの提出ステータスがsubmittedなら完了。draft/reopenedは未完了。点数や未採点表示からは判定しません。
- 小テスト：完了した受験があれば完了。進行中や期限超過の受験が残っていれば未完了です。表示文言はMoodleから翻訳を取得します。
- その他の教材：Moodleが設定している自動完了条件の状態を、コース一覧の読取APIから取得します。確認のために教材を開いて閲覧済みにする処理は行いません。
- 自動完了が未設定、未知の表示形式、権限不足、取得失敗などでは不明のまま保存します。未完了だと断定せず、別枠から確認できます。
- カレンダーフィードの期間外になった保存済み課題も、ログイン中は提出状態を再確認します。

大学の公開ログイン画面は確認済みですが、ログイン後の大学固有の提出画面は利用者のログイン後に実運用確認が必要です。判定はMoodle公式のAPIと標準レンダラーに基づいており、不明な構造は推測で完了にしません。

登録後はアプリ起動時・定期同期・「今すぐ同期」で取得します。課題は `~/Library/Application Support/UniversityTaskManager/tasks.sqlite` に保存します。オフライン時も前回保存分を表示します。

## 常駐・自動同期

- メニューバーの本アイコンに未完了件数を表示します。直近の課題、取得元別の状態、次回同期時刻を確認し、一覧・設定・手動同期・終了を操作できます。
- ウィンドウを閉じてもアプリは終了せず、同期管理サービスは継続します。「終了」またはCommand + Qで完全終了します。
- 初期設定は自動同期ON・30分間隔。設定から15分／30分／1時間／2時間と、自動同期ON/OFFを変更できます。OFFでも手動同期は可能です。
- スリープ中に定期実行を保証しません。復帰時は期限の来た取得元だけを1回ずつ同期し、逃した回数を再実行しません。ネットワーク復帰時も実行予定を確認します。
- 同時に同期を複数実行しません。実行中の自動トリガーはまとめ、追加の手動要求は1回分だけ待機させます。
- 通信・一時サーバーエラーは1分・2分・4分…と間隔を延ばして再試行し、設定間隔を上限にします。ログイン切れ・設定やデータ形式の問題は該当取得元を一時停止します。手動同期・再連携の成功で再開します。
- 起動時は非対話のKeychain読取、定期同期はメモリ上のスナップショットを利用します。自動同期はKeychainを再読取したり大学のログイン画面を開いたりしません。許可操作・手動同期・連携操作だけが対話的な認証情報の読取を行います。
- 同期設定・試行時刻・再試行回数・一時停止フラグのみUserDefaultsへ保存します。URL・Cookieは含めません。成功時刻は引き続き課題と同じDBトランザクションで更新します。
- 「Macログイン時に起動」はOSの状態を表示し、利用者がON/OFFを操作したときだけSMAppServiceで変更します。勝手に有効化しません。OSが承認を要求した場合は設定画面から案内します。
- 実時間を進めないテストで同期間隔・スリープ復帰相当・認証停止・重複防止を検証しています。実際の再ログインによる自動起動、長時間の実運用、大学側セッションの寿命は利用環境での確認が必要です。

## 課題・締切の通知

通知は「設定」→「課題の通知」をONにし、macOSの確認で許可してください。初期状態はOFFで、起動時に許可を要求しません。ONにした後に「テスト通知」を押すと3秒後の通知を予約します。拒否した場合は「macOSの通知設定を開く」から許可し直してください。

- 新しい課題、締切の24時間前／3時間前、締切変更、締切を迎えた未完了課題に対応します。種類別のON/OFFと通知音を設定できます。
- 提出状況が確認できた未完了課題だけが対象です。未確認・取得不能・取得範囲外の課題は通知しません。最初の有効化・LMSごとの初回取込では、既存課題や過去の締切を一斉通知しません。
- 同期で提出済みと確認できたときや締切変更時に、古い予約と通知センターの古い通知を取り消します。通知をクリックするとアプリ内の該当課題を表示します。大学のページへ自動アクセスする操作ではありません。
- macOSへ予約済みの通知はアプリ終了後も届く場合があります。終了中は同期しないため、別端末での提出・締切変更は次回同期まで反映できません。予約を止めたいときは通知をOFFにしてから終了してください。
- UUID・締切・変更世代・通知種類による安定したIDと登録履歴を保存し、再同期・再起動での二重登録を抑えます。登録失敗した新規／変更通知は最大1時間保持し再試行します。履歴に課題名・URL・Cookieは保存しません。
- 予約は近い順に最大48件で、起動中は毎分・同期後に補充します。新規／変更の即時通知は1回最大5件、未送信は最大100件まで保持します。長時間アプリを終了している場合、全課題の通知を保証しません。
- 集中モード、Macのスリープ、macOSの通知設定で表示が遅延・抑制されることがあります。通知は提出確認の代わりではありません。テストはOSアダプターを模擬しており、実機での表示・クリック・終了後配信は「テスト通知」などで別途確認してください。

通知の仕組みは[Appleのローカル通知ドキュメント](https://developer.apple.com/documentation/usernotifications/scheduling-a-notification-locally-from-your-app)を参照しています。

## WebClassの接続

1. アプリの「設定」を開き、下へスクロールして「WebClassにログイン」を押します。
2. HOPPIIから法政大学の統合認証でログインします。パスワードや多要素認証は公式画面に入力します。
3. WebClassの課題一覧まで自動的に進みます。進まない場合はHOPPIIの「学習支援システム(WebClass)」、続いて「課題一覧へ」を選びます。
4. 「連携して同期」を押すと、WebClass用CookieをKeychainに保存し、課題・締切・実施状況を取得します。

調査用の内蔵ブラウザと、このアプリのWKWebViewは別セッションです。内蔵ブラウザからCookieをコピーする機能はなく、アプリでも初回ログインが必要です。受験中・回答中の別ログインは避けてください。ログインが切れたときは「HOPPIIで再ログイン」を押します。

大学の実際のログイン後画面・公開フロントエンド・本人の読取APIで接続経路とレスポンス形式を確認しました。2026年10月22日、利用者の環境でアプリ内ログインから初回同期まで成功したことを確認しました。すべての教材種類・状態を実データで網羅した検証ではありません。

- CSVダウンロードは不要です。画面と同じ `score_summary_table` の `dashboard` / `courses` / `contents` をGETします。
- 本人の実施記録だけを判定し、教員用のコース・他学生の成績取得APIは使用しません。成績・氏名・ユーザーIDはTaskに保存しません。
- 学期・年度で自動除外せず、受講中として取得できる授業を確認します。締切なし・非公開教材は除外します。
- 教材IDとコースIDを使うため、タイトルや締切が変わっても同じ課題を更新します。
- 合格点が公開されている教材は不合格なら未完了、合格なら完了です。合格点なし、または非公開成績の教材は、公式の学生向け絞込みと同じ実施記録を使います。
- 記名アンケートは回答記録で判定します。匿名アンケートや判定情報不足は不明として別枠に残します。点数0を未実施と誤認しません。
- 大学統合認証・HOPPIIのCookieやパスワードは保存しません。WebClass用Cookieだけを専用のKeychain項目で管理します。
- 通信は固定のHTTPS読取先に限定し、SSOリダイレクトを追跡しません。最大3並列・同期全体60秒・1応答8MiBです。
- 1授業でも取得に失敗すれば、その回のWebClass保存を行いません。Moodleとの同期は独立しており、一方の失敗でも他方は同期できます。
- 元ページへのリンクは授業ページです。教材を自動的に開いて受験開始や閲覧完了を発生させません。

登録後は起動時・定期同期・「今すぐ同期」で両方のLMSを取得します。各LMSの最終成功時刻とエラーを個別に表示します。通知をONにすると確認済み未完了課題の締切通知を予約します。

```sh
cd backend
npm ci
npm test
npm run build
```

`package-lock.json` を共有し、依存のバージョンを固定しています。

SwiftのMoodle/WebClass ConnectorはTypeScriptを呼ぶ薄いアダプターです。WebClassは法政大学の調査済み構成に対応し、他大学・別ホストには対応していません。

バックエンドはリクエストごとに起動し、JSONを標準入力・標準出力で受け渡します。HTTPサーバーやポートは使いません。トークン付きURLやセッションCookieは引数・環境変数・通常ファイルへ渡さず、Keychainから読み取った値を標準入力だけで渡します。NodeはCookieやディスクキャッシュを保存しません。

## 保存方式と制限

ターミナル起動を維持するため、Core Dataを採用しmacOS 13対応を継続しました。保存先とDB形式・Keychainの識別子は変更していないため、既存の課題・登録済みURLを引き継ぎます。Swiftは保存の読み書きを担当し、更新する内容はTypeScriptが決定します。

- UIDで同じ課題を更新します。締切変更でも課題IDと初回検出日時を保ちます。
- フィードから消えた課題は削除・完了扱いにせず、取得範囲に見つからないことを表示します。
- VEVENTのDTENDを優先し、なければDTSTARTを使います。終日のDTENDは排他的なため、その直前を期限とします。一般の予定も候補として表示する段階であり、課題のみの厳密な抽出は今後の実データ調査が必要です。
- UTC、IANA TZID、浮動日時、終日、折り返し行に対応します。繰り返し予定・未知のタイムゾーン・破損データは黙って捨てず、同期を失敗にして保存済みデータを維持します。
- 利用者によるテスト通知の表示は確認済みです。実際の締切通知・提出後取消・終了後配信・Mac再ログインの確認と、一般配布用署名・公証は残っています。Version 1完成ではありません。

WebClass調査で確認した接続先：`hoppii2025.hosei.ac.jp/portal/` → `idp.hosei.ac.jp/openam/` → HOPPIIの`portal/sso/Parm.php` → `lms2025.hosei.ac.jp/webclass/`。判定ルールは、大学が配信するダッシュボードの学生向け完了/未完了フィルターを参照しています。実アカウントの生データや認証情報はテスト・Gitに含めません。
